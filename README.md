# Team-I 主动追证剧场

`Team-I 主动追证剧场` 是一个独立的像素风交互式前端，用游戏化方式展示跨境电商连续审计中的主动追证闭环。它不是传统后台系统，也不是静态流程图，而是把多源数据融合、多模型 Agent 协作、OpenCLAW 受控动作、证据护照、人工复核和策略回流做成一条可以点击、推进和自动播放的审计关卡。

页面中的“黑灰产小偷”代表风险行为主体，“Agent 太阳”代表主动追证能力。小偷沿着关卡路线向前逃逸，系统在每一关用不同技术模块补齐证据、检索反证、约束动作并沉淀策略，最终证明黑灰产无法逃出完整审计闭环。

## 项目定位

本项目用于比赛展示中的“技术可视化讲解”部分。主系统中的后端、Agent、模型、数据库和实验结果都比较难在现场直接解释，因此该前端把底层技术抽象成一个可玩的审计世界，让评委能够在一屏内看到完整链路如何运转。

它重点回答三个问题：

第一，Team-I 的系统不是一次性规则命中，而是一条连续主动追证链。页面通过 7 个关卡展示风险从业务流进入审计系统后，如何逐步补齐证据缺口。

第二，Team-I 的系统不是单模型问答，而是多模型 Agent 与受控工具协作。页面中的模型议会、OpenCLAW 工坊、证据大陆和证据护照分别对应后端中的智能体、动作注册、图谱融合和审计复核输出。

第三，Team-I 的系统不是只做单次处置，而是可以学习回流。页面中的学习回流炉展示候选模式、风险模式、案例记忆和策略权重如何在人工确认后进入下一轮审计。

## 快速开始

环境要求：

- Node.js 18 或更高版本
- npm 9 或更高版本

安装依赖：

```bash
npm install
```

本地开发：

```bash
npm run dev
```

浏览器打开：

```text
http://127.0.0.1:5178/
```

构建发布版本：

```bash

```

```bash

```

## 一屏式游戏结构

整个页面固定为一屏，不依赖上下滚动。布局分为五个区域：

顶部是全局 HUD，展示项目标题、风险案例数、证据条目数、追踪轨迹数、模型调用次数、轨迹在线状态和当前难度。

左侧是地图和输入侧，包含世界地图、多源地层和当前动作。它说明案件从哪些业务数据进入系统，以及当前正在执行哪个追证动作。

中间是主游戏世界，展示黑灰产小偷、Agent 太阳、七个关卡、路线光带、当前案件卡片和 Boss 血条。用户可以点击关卡，也可以用底部按钮推进。

右侧是案件和学习侧，包含当前 Case、学习回流炉和能力星轨。它说明当前风险类型、学习写回状态和系统能力覆盖。

底部是技术控制台，包含模型议会、OpenCLAW 工坊、证据大陆、证据护照、追证能量曲线和操作按钮。

## 操作方式

页面支持三种操作方式：

第一，点击底部 `前进` 和 `后退` 按钮，在关卡之间移动黑灰产小偷。

第二，点击 `打开关卡`，查看当前关卡对应的技术解释、实验图表和输出结果。

第三，点击 `自动跑`，让小偷沿审计路线自动推进，模拟系统持续追证的过程。

键盘也可以操作：

```text
ArrowRight / D    前进
ArrowLeft / A     后退
Enter / Space     打开当前关卡
```

## 难度与三个案例

页面使用 `Easy`、`Normal`、`Hard` 三种难度对应统一业务场景下的三个风险案例。

`Easy` 对应 `AER-003 补贴套利观察`。这是弱信号场景，风险分较低，系统更强调观察池、证据不足和持续监控。它展示简单风险不一定需要高强度主动追证，可以先进入观察和策略沉淀。

`Normal` 对应 `AER-002 空包虚假交易与评论操纵`。这是中高复杂度场景，物流异常、评论集中和退款行为互相增强，需要结合多源融合与反证检索判断是否为真实风险。

`Hard` 对应 `AER-001 团伙刷单骗补`。这是高风险 Boss 场景，设备、账号、IP、退款和补贴台账形成团伙化闭环，需要完整经过主动追证、OpenCLAW 受控动作、证据护照和模式写回。

## 七个关卡

### 1. 业务风险空间

第一关对应风险信号发现。订单、退款、补贴、设备、IP 和行为序列进入审计视野，风险信号 Agent 识别异常火种。页面中的起点集市代表业务流，黑灰产小偷从这里开始移动。

这一关回答“风险从哪里来”。它不是直接给出结论，而是把实时业务流中值得追踪的异常组合标记出来。

### 2. 多源数据接入

第二关对应多源异构数据接入。订单、支付、退款、物流、评论、设备、IP、补贴台账和外部特征被统一接入。页面中的多源地层代表不同业务数据源，弹窗中的柱状图展示来源增加后证据充分性如何提升。

这一关回答“为什么不能只看单表”。单一订单表只能发现局部异常，多源接入才能覆盖审计需要的完整证据维度。

### 3. 融合与案例构建

第三关对应证据图谱构建。系统把账号、设备、IP、支付账户、订单、物流和补贴记录连接成案件图。页面中的证据森林和底部证据大陆展示节点、边和中心案件之间的关系。

这一关回答“多源数据如何变成可解释证据”。它不是把数据堆在一起，而是把关系、时间线和证据强度组织成可查看的图结构。

### 4. Agent 主动追证

第四关对应主动追证核心。Agent 太阳代表系统根据证据缺口持续选择下一步动作。它不会停留在第一次命中规则，而是继续追问支持证据、反证和不确定性。

弹窗中的曲线展示主动追证逐轮提升证据充分性。传统规则或固定清单会较早停滞，而 Team-I 的主动追证闭环会随着每轮动作持续补齐证据缺口。

### 5. OpenCLAW 受控动作

第五关对应受控工具执行。OpenCLAW 工坊展示关系扩展、退款簇查询、支付簇查询、物流追踪、补贴台账、促销对照、行为序列和反证检索等动作。

这一关回答“Agent 为什么不是随意调用工具”。每个动作都经过受控注册、参数约束、观察结果记录和轨迹留痕，保证审计过程可以复核。

### 6. 证据护照与人工复核

第六关对应证据护照生成。系统把支持证据、反证、不确定性、证据覆盖、版本信息和人工门禁汇总为复核包。页面中的护照卡片展示当前案件是否达到可复核门槛。

这一关回答“如何让模型输出进入审计语境”。结论不是一句自然语言回答，而是一份带证据、反证和复核状态的审计护照。

### 7. 模式学习与策略回流

第七关对应模式学习写回。人工确认后的候选模式会沉淀到风险模式库、案例记忆和策略权重中。页面中的学习回流炉代表系统把一次审计经验转化为下一次追证的先验。

这一关回答“系统如何持续进化”。它不是只完成当前案件，而是把已确认经验写回，影响后续案件的路由和动作排序。

## 底部技术控制台

### 模型议会

模型议会展示多模型 Agent 的调用分工。7B 模型承担高频路由、风险信号、断言生成和追证动作；14B 模型承担模式匹配、证据护照和模式学习等更强推理任务。

这个模块说明 Team-I 不是单模型堆叠，而是按照任务复杂度拆分模型角色。

### OpenCLAW 工坊

OpenCLAW 工坊展示系统可调用的受控动作。每个动作都是审计链路中的一个明确能力，例如关系扩展、退款簇查询、支付簇查询、物流追踪、补贴台账、促销对照、行为序列和反证检索。

这个模块说明 Agent 的“行动”是有边界、有记录、有审计轨迹的。

### 证据大陆

证据大陆展示案件图谱。中心节点是风险案件，周围节点是订单、设备、IP、支付、物流、补贴和外部特征等证据。

这个模块说明多源融合最终会落成可解释图结构，而不是不可读的黑箱分数。

### 证据护照

证据护照展示当前案件的证据充分性和复核状态。它把支持证据、反证、不确定性和人工门禁压缩成一个可读的审计输出。

这个模块说明模型结果最终需要进入可复核的审计交付物。

### 追证能量曲线

追证能量曲线展示主动追证逐轮补齐证据的过程。曲线不是静态图片，而是由 CSV 数据在前端重建。

这个模块说明 Team-I 的优势体现在连续动作后的证据充分性提升。

## 与主审计系统的关系

本仓库是独立前端展示项目。它可以单独运行，也可以连接主审计系统后端 API。

单独运行时，页面使用内置 fallback 数据，适合现场讲解、GitHub Pages 展示和离线预览。

连接后端时，页面会读取真实 API 返回的案件、图谱、路由、证据护照、候选模式和策略权重，使游戏世界与当前审计数据库保持一致。

项目可以部署为任意静态站点。先在本地执行：

```bash
npm ci
npm run build
```

构建产物位于 `dist/`，可以发布到 GitHub Pages、Vercel、Netlify、静态对象存储或任意 Web 服务器。

如果页面部署在 GitHub Pages 的仓库子路径下，Vite 已使用相对路径构建，静态资源和实验 CSV 可以正常加载。

如果需要在 GitHub 上开启自动部署，可以在仓库中补充 GitHub Pages workflow；推送 workflow 文件需要 GitHub token 具备 `workflow` 权限。

## 设计原则

这个前端遵循三个原则：

第一，业务场景是入口。页面始终围绕跨境电商风险追证和三个典型 Case 展开，而不是单独介绍技术名词。

第二，技术能力要可见。每个关卡、面板和图表都对应后端能力，避免把多模型 Agent、OpenCLAW、证据图谱和策略写回藏在文字说明里。

第三，展示过程要可玩。用户可以推进小偷、打开关卡、切换难度和自动播放，使审计闭环像一个会动的世界，而不是一张静态流程图。
